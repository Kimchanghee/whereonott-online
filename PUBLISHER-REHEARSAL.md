# Publisher rehearsal

Run `pwsh -NoProfile -File scripts/dryrun-fixture.ps1 -Case pass`, then `-Case invalid-source` and `-Case invalid-built`. Expected exit codes: 0, 1, 1. The negative failures must specifically report product.optionDetail missing and dist/ads.txt missing, respectively. `node --test tests/*.test.mjs` also checks default-deploy denial, traversal rejection and a missing dry-run post.

The runner copies only authoring inputs into a uniquely named OS temporary directory. It reuses trusted installed packages through per-package links, with a new node_modules directory and stage-local .astro/.vite caches. No package installation, credential/config copying, or real release build occurs. This is write/cache isolation for trusted build code, NOT an OS security sandbox. The child publisher is bounded to 180 seconds. The stage is removed in finally; protected src/public/dist/ops/content hashes must match before and after. A marker blocks deployment even with -AllowDeploy; unmarked deployment is disabled by default. Dry-run receipts remain in the deleted stage and are not public publication receipts.

Only the stage gets a loopback preview configuration when real ops configuration is absent. No real product approval follows from a deliberately fake fixture. Exact SKU/option and affiliate landing identity, factual source review, image rights/visual QA, account/program approval and trusted editorial authorization remain separate manual gates. Current gates check fields and rendering, not the truth of caller-provided evidence. Real deployment configuration, a public post receipt and live product verification are not established by these tests. Renderer/schema/gate rules are unchanged.
